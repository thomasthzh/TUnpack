# T解压：需求与技术路线

## 已确认的业务

2026-11-09 用户要求全新轻量 Windows 解压缩工具，参考本地 OnlyUnzip 1.5.3；授权下载并使用 REA、研究高质量开源项目。
用户确认：成功后原包移入回收站；同名保留并自动改名；密码范围是本地保存/导入的候选、文件名和同目录提示，不做无限暴力破解。

1. 必须：内容识别，不能信任扩展名；支持伪后缀和视频中追加的 ZIP/7z/RAR。
2. 必须：识别并恢复已知 apate 头部伪装；不修改源文件，允许另存原包。
3. 必须：密码保存、导入、成功密码复用、候选排序与快速验证；密码不写进日志和命令行。
4. 必须：自动解压新产生的嵌套包，正常 Office/APK 等 ZIP 容器不自动拆散。
5. 必须：手动添加与拖入队列；默认在原包所在目录输出，也能选择目录；界面不卡住、进度可见、任务可取消/重试。
6. 必须：多卷归组、缺卷反馈；无法确定顺序的改名切片允许手工明确排序。
7. 必须：解压及嵌套全部成功、输出完整后才回收源包；失败/取消保留原包和可用输出。
8. 必须：复用成熟解压引擎；避免重复解析器、全文件哈希、每候选启动 CLI。
9. 综合工具补充：创建 7z/ZIP 压缩包。

官网当前制作决定：用户在2026-11-17明确禁止继续使用Blender，要求直接做动画并保留英雄镜头。主片仅用一套矢量时间轴，内容识别/改名分卷/候选验证/嵌套与结果必须通过动作成立；CU与桌面/浏览器自动操作继续禁止。旧视频只保留兼容URL，不能代表用户认可。

## 路线选择

| 路线 | 取舍 |
|---|---|
| **采用 C++20 + Win32 + bit7z v4 + 7-Zip ZS DLL** | 无 WebView/.NET 依赖；直接使用成熟引擎和输入流；UI、DPI、键盘需要认真处理。 |
| C# + WinForms/WinUI | 开发快，但运行时与部署体积不利于本次轻量优先目标。 |
| Rust + Windows API + 7z FFI | 可行，额外 COM/桥接维护没有足够收益。 |

实现采用单一输入视图：只读映射文件 → 可选 apate 还原 → 偏移/长度视图 → 多卷拼接 → 7z。只做当前需求用到的模块。
默认在所选输出父目录创建以原包命名的文件夹，已有同名文件夹时创建 `(2)` 等新目录，保留既有内容。
队列添加不自动开始；用户可检查设置后点击开始，处理时仍可添加。

## 参考和证据

- [REA](https://github.com/morluto/rea)：已下载源码和 6.8.0 官方发布包，使用便携 Node 24.22.2，不改系统/Codex 配置。实际报告在 `docs/evidence/`。PE 静态检查不是恢复 Python 源码，也不证明业务语义。
- [OnlyUnzip](https://github.com/PPJUST/OnlyUnzip)：采用原有五项业务意图，独立重写。当前 main 已是 2.x，不能当成本地 1.5.3 的逐字源码；版本核对另记在进度中。
- [bit7z](https://github.com/rikyoz/bit7z)：采用 v4.0.10 的 7z DLL 封装、流输入、回调、选择性解压，MPL2。仅扩展库的卷路径映射/实际开卷观测接口，修改保留原许可与 `patches/bit7z-volumes.patch`，不改解压算法。
- [7-Zip ZS](https://github.com/mcmilk/7-Zip-zstd/releases/tag/v26.05-v1.5.7-R1)：本地旧版为 22.01，已下载官方 26.05-v1.5.7-R1，校验发行摘要后解包取 DLL，没有运行安装器；便携版附对应许可。
- [NanaZip](https://github.com/M2Team/NanaZip)：参考原生集成/DPI 与 UI-Core 分离；不复制其图标。
- [unblob](https://github.com/onekey-sec/unblob)：借鉴候选签名后验证结构；不引入整套运行时。
- [apate 协议](https://github.com/rippod/apate/blob/main/apate/Program.cs)：独立实现格式兼容，不复制 GPL 实现。F=N+L+4；原头 min(L,N) 字节倒序存于 max(L,N)；末尾 uint32LE 为 L。
- [libarchive](https://github.com/libarchive/libarchive)：暂不增加第二引擎；其 RAR5 加密支持不能替代 7z。

## 识别和密码约束

签名只是候选，交给引擎打开/校验后才算识别成功。先开头与尾部快探；必要时流式深扫描，显示进度，可取消。
真实 DOCX/EPUB/APK 识别内部结构；不因为扩展名直接跳过，伪装成 DOCX 的普通压缩包仍处理。
完全改名的 .7z.003 可能没有任何格式/序号字段，不能单文件保证还原。根据同目录首卷、编号、长度和尾部元数据 CRC 归组；改名末卷或一个改名中间卷只有唯一解才自动采用，多个合法首卷/候选时交给手工分卷。信息不足时要求首卷及顺序，保留源文件名。
ZIP/ZIP64 的目录和尾记录用于定位真实偏移与长度；7z 尾 Header 用于辨认缺首卷、倒序或覆盖头部。重建仅修复有结构依据的头部，缺失正文保持不可读；最终由成熟引擎验证完整数据。
密码优先本次指定、父包/同批成功、关联目录、历史使用频率。ZIP先无密码读元数据；普通ZIP、仅识别与另存不做密码KDF。加密ZIP最便宜条目已知且不超过1MiB时，先预检前4个排序原候选（含UTF-8/系统代码页变体），对通过头部者强制SDK完整条目验证，再用原并行预检处理剩余候选。头部匹配不能替代正文验证；不支持方法保留引擎错误，不提示补密码。大/未知条目沿用全量批量预检策略，避免新增强制正文预读。其余格式按SDK最低成本条目验证，最后完整解压校验。元数据识别与完整测试分开，CLI `inspect --verify` 使用 SDK 全包测试模式，不生成解压文件。
7z KDF 有实际成本/锁竞争，不承诺简单多线程倍增；密码提速要和逐候选整包 CLI 测试做实测比较。

## 界面

单一工作台：顶部队列/密码本切换，主区域拖放区和任务列表，底部输出目录、嵌套与清理选项、本批密码、开始/停止。低频的识别/另存/明确拆容器放在任务操作菜单。
0.8任务可覆盖输出/嵌套/回收/深识别，未覆盖者开始时跟随本批设置；暂缓待开始项不执行但保留源依赖。工作台后台合并保存非敏感队列/结果/草稿/视图，正常关闭前提交，恢复不自动执行，旧运行项转中断需重试；不保存密码输入、密码草稿、搜索和显示状态。只在同一用户登录会话内保持一个GUI工作台，后续文件打开请求归并；源无法访问可重新定位，手工组保留槽位、自动组重新配卷。
0.9批次可在当前任务结束后暂停并继续，立即停止优先；根输出在实际目标确定时发布，嵌套不改根入口，取消/中断恢复保留已记录路径，重试不续写旧结果。自动提示与导入共用严格UTF-8读取，分别64KiB/16MiB上限；坏提示按文件隔离，文件名新增去归档/分卷后缀候选且保留原候选。目录中单个条目变化继续，其余遍历错误/根错误/取消不冒充完整扫描。
0.10追加原因筛选（需密码/卷问题/源问题/校验）仅匹配Attention，路径查找覆盖源/创建目标/内层失败/结果。当前显示失败或取消项可批量准备重试，运行/关闭时禁用，不自动开始；新筛选编号追加，旧会话兼容。仅Waiting槽位参与多选稳定上/下/最前/最后排列，暂缓保持；Running划分边界，历史槽固定，筛选中不重排；保留多选/独立焦点/扩选锚点，不通过逐项get/move实现。
0.11进度单位由生产点显式传递，GUI/CLI复用单一阶段门限；阶段/单位/总量变化、已观察计数回退立即发布，同阶段分别90ms/1s。运行计数与steady-clock用时不入会话，百分比仅本阶段；无整体ETA/速度推断。配卷有可取消边界，已解析标记只用于当前集合，nested按自身结果重设并同层共享元数据；类型化取消及SDK E_ABORT优先传播，禁止回退误报缺卷/错误密码/校验失败。
0.12结果导航共用一套原生路径：目录打开内容，文件使用[系统精确选中](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shopenfolderandselectitems)实际生成路径，含重名后的uniquePath；不执行结果文件。单选菜单可定位来源首项或记录的内层问题路径，运行中可用、关闭时禁用，命令重新检查。缺失/不可访问返回完整路径错误，不退父目录或外层包。原生测试只准备绝对PIDL，不调用Explorer执行。
0.13嵌套问题可单独准备重试：Extract的Attention/Cancelled记录有位于根输出内且不同于根来源的failedFile时，生成全新任务，不复制父身份/手工分卷/创建目标/容器标记。settings取父专用或准备时本批快照，output改为failedFile.parent；密码输入仍按本批/密码本使用，不进入会话。直接入口和补卷共用生成规则，缺失文件明确反馈、重复交现有队列键处理，不自动开始；父记录/根输出保持，不宣称续传或已完成所有siblings。深层子包成功后当前层后续读取失败，递归边界只补回缺失的当前child路径，不覆盖已有更深问题。
分卷使用有序原生列表，显示首卷与每卷路径/大小，支持补拖、添加、上移/下移；保存后才修改任务，返回可保留草稿。密码本搜索、默认遮住已有密码、反馈新增/重复数量；保存失败保留草稿并允许真正重试。
队列按任务身份保持选择，虚拟列表按需提供行，归组放到后台，进度刷新节流。回收前以引擎实际源集合检查同队列的其他读者；仍有依赖时明确保留，清理时禁止新入队任务抢用这些源。
0.5的查找与状态筛选只影响显示，开始仍作用于全队列等待项；筛选中不重排，批量操作仅作用于可见选中项，全部完成项清除明确标注。后台更新合并为90ms批次，行顺序未变时不重建原生选择。分卷支持多选整组移动与显式自然排序，队列/分卷支持复制文件或路径的粘贴；密码新增预览与真实保存共用分类规则且不写库。
浅色中性背景、深色文字、青绿色主操作，Segoe UI/微软雅黑系统字体，不加载网络字体。不做网页 hero/聊天界面。
原生控件保留键盘和辅助功能；Tab/Ctrl+O/Delete/Enter、焦点可见、DPI 自适应；状态包含原因及下一步，颜色不作唯一提示。
0.4.1补齐虚拟列表的[查找通知](https://learn.microsoft.com/en-us/windows/win32/controls/lvn-odfinditem)及[精确/前缀/回绕语义](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/ns-commctrl-lvfindinfow)，按任务身份保留选择、焦点和扩选锚点。密码文本导入限制单文件16MiB，严格验证UTF-8，部分成功逐项报告；不凭TXT后缀将压缩数据加入密码本。

## 验收

构建可运行 exe；真实测试普通/改后缀 ZIP、7z、加密头、错误密码、嵌套、追加偏移包、apate、正常文档、标准/手工排序分卷、冲突/取消/越界路径。
自动回归只使用合成/公开固定样本。2026-11-11 用户另授权使用 <CORPUS_ROOT> 和 OnlyUnzip 现有密码进行真实解压测试；真实输入全部保留，输出独立到 <CORPUS_OUTPUT>。回收测试仍需针对实际样本单独确认。
记录 exe/DLL 大小、启动/空闲内存、识别与密码样本耗时；没有测得的数据不宣称“超高性能”达成。
