# T解压

[官网与产品短片](https://tunpack.thomasthzh.top/) · [下载 Windows x64 便携版](https://github.com/thomasthzh/TUnpack/releases/tag/v0.13.1)

Windows x64 原生轻量解压工具，当前版本 0.13.1。运行解压目录中的 `T解压.exe`，无需安装 .NET、Python 或 WebView。图标使用三层错位、边缘厚度与光影，ICO 包含 16–256 像素九个尺寸。

## 构建

需要 CMake 3.24+、Git、Python 3 与 C++20 工具链。当前发布使用 WinLibs GCC 16 / Ninja 构建；也提供 CMake 的 MSVC 配置。获取依赖时需已安装 7-Zip，或传入其命令行路径；构建工具不是软件运行依赖。

```powershell
python scripts/fetch_deps.py --seven-zip "C:/Program Files/7-Zip/7z.exe"
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 8
python tests/download_fixtures.py
ctest --test-dir build --output-on-failure
python scripts/package.py
```

生成 `dist/TUnpack-0.13.1-windows-x64.zip` 和 `SHA256SUMS.txt`，保留解压目录 `dist/T解压/`。MSVC 可在开发者终端使用 `cmake -S . -B build -A x64` 与 `cmake --build build --config Release`；打包脚本支持可执行文件在 `bin/Release`、附属引擎在 `bin` 的布局；本轮未对 MSVC 实际编译验收。首次 CMake 配置会联网获取固定版本 CPM / 7-Zip 接口头 / ghc::filesystem，不应关闭 TLS 校验。

`tools/` 不入库。bit7z 固定 [v4.0.10 源码](https://github.com/rikyoz/bit7z/tree/0f03717920442abcdba80183534931c867feb9c0)（MPL-2.0）并应用本项目卷路径补丁；引擎来自 [7-Zip ZS 26.05 官方发布](https://github.com/mcmilk/7-Zip-zstd/releases/tag/v26.05-v1.5.7-R1)，核对官方校验值后用 7-Zip 展开，不运行安装器。脚本保留下载，重复执行会核对版本与补丁，不删除文件。第三方完整许可与对应源码见 `THIRD-PARTY-NOTICES.txt`，便携包同时附带 MIT、依赖许可和使用说明。

拖入文件/文件夹，或点击“添加文件”。检查输出目录和选项后，点击“开始队列”。默认在原包目录创建同名文件夹；已有同名内容时使用新名称。运行中仍可添加任务。

0.13.1修复标准ZIP原生分卷（`.z01`、`.z02`…末卷`.zip`）：拖目录或任一卷自动归为同一组；手工按物理卷序排列，`.zip`放最后，程序自动选入口。升级前请退出旧版工作台，再运行新版。

选择一个或多个任务，点击“任务设置”可指定各自的输出目录、是否展开嵌套、是否回收源包及深度识别；没有专用设置的任务在开始时跟随本批设置。“保存设置”只保存，“保存并待开始”准备下一次处理，均不会立即执行。待开始项可暂缓或继续，暂缓项仍保护源文件，开始全部会跳过它们。

工作台自动保存队列、已完成结果、处理设置、分卷/任务设置草稿、查找筛选、列宽及窗口尺寸，下次打开恢复现场。恢复后不会自动开始；上次正在处理的任务标为中断，需显式重试。已写出的文件保留，解压目录一创建就发布给队列，运行中可“查看当前输出”，取消后可“查看保留结果”；工作台恢复保留已保存的路径。异常退出仍可能丢失最后一次保存后的变化；重试从头处理并创建新目录，不续写旧结果。密码输入、新增密码草稿、密码搜索和显示状态不进入工作台记录；密码本仍使用原有 DPAPI 加密文件。正常关闭前等待保存，失败时提示并保留旧记录。

同一登录会话内，用“打开方式”再次交给 T解压的文件会加入已有工作台，不另开队列；重复待处理项会跳过。来源移动、改名或断开连接时，任务提供“重新定位源”入口，保留处理设置；手工分卷只换对应位置，自动组在新路径重新配卷。没有注册文件关联或修改系统右键菜单。

长批次可在“任务操作”中选择“完成当前后暂停批次”，也可按 Ctrl+Shift+空格请求或撤销。当前任务会完成，后续等待项保持，点击“继续全部”再处理；“停止队列”仍可立即请求取消当前操作。

队列支持多选、批量重试/移除；多个等待项可一起上移/下移，也可在任务操作中移至最前/最后。只调整等待位置，正在处理和历史记录保持；运行任务两侧各自排序，不能跨过当前任务，暂缓标记和专用设置跟随原任务。菜单或对话框打开时再次交入文件，会加入队列并保留原选择；分卷自动合并后，选择、键盘焦点和 Shift 扩选起点会跟随合并后的任务。配卷在后台执行，列表使用原生虚拟行，支持键入文件名前缀查找；状态区汇总待开始、处理中、完成、需处理、取消数量。选中任务可查看完整路径、失败原因及下一步，未知总量阶段使用活动进度条。右键菜单跟随点击位置，键盘菜单跟随焦点行，多个普通文件可一起切换任务操作。

队列提供文件名/路径查找和状态筛选，显示当前项数与总数；也能按需要密码、分卷问题、来源问题、校验未过筛选，查询覆盖来源、内层失败文件和实际输出路径。查找和筛选只改变显示，“开始全部”始终处理整个队列的等待项；筛选中不调整执行顺序，点击“重置”后可上下移动。补好密码或卷后，可在任务操作中选择“重试当前显示的失败/取消项”，只将当前查找/筛选范围内的合格项准备好，不自动开始；运行中须先暂停批次或等结束。准备后项目可能离开当前筛选，“开始全部”仍处理全部等待项，包括隐藏项。缺密码/缺卷任务有直接定位按钮。后台通知按批刷新，可见行顺序未变时保留原生选择状态，只更新变化行。

嵌套包缺密码、校验问题处理好后，或内层解压已取消，可在任务操作选择“只重试内层包”。先填写本批密码或导入密码本，再加入独立内层任务，点击开始全部处理；无需重复解压外层。内层输出留在问题包所在目录，继承父任务专用设置或准备时的本批设置，已有同名结果使用新名称。内层补卷也遵循同一输出规则。原任务仍保留失败/取消记录，不会因为单个内层成功就标为全部完成；尚未处理的其他内层包不会自动接续。

缺卷后补齐文件再重试，会重新识别卷组；错误密码可补充或导入后重试。嵌套包失败时显示内层完整路径；补内层分卷会建立单独任务，保留外层任务及输出。取消任务只提示重试，识别结果直接显示 ZIP/7z/RAR 等真实格式。

布局支持按DPI缩放字体、图标、控件边缘及下拉项高度，滚动范围会同时考虑横纵条的占位；窗口放大后移除不再需要的滚动条。列表自动适配实际客户宽度，手动调整列宽后保留选择，并从原始DPI缩放，避免反复跨屏累积误差。Tab按搜索、列表、任务操作和设置的顺序移动，切页保留最后工作控件和滚动位置，焦点行或编辑光标会滚入视野，宽密码框在窄窗口中也会跟随输入位置。隐藏页面的后台列表刷新保持隐藏。运行时的禁用操作对快捷键同样生效。三张列表提供空态提示，接收拖入时高亮；分卷反馈可显示两行。

运行中的进度明确区分字节、文件、候选或项目数；百分比对应当前阶段，未知总量显示已处理数量。状态区显示本次任务用时，阶段变化不会被普通进度节流挡住；用时与计数只在运行内存中更新，重试重新计时，不写入历史会话。命令行 --progress 也输出单位并及时报告新阶段。配卷在目录、候选及编号遍历边界检查停止，成功解析的根输入与本批目录快照复用，嵌套新文件独立判断；补卷重试仍刷新。停止需要当前系统调用或引擎内部计算返回，不承诺固定响应时延。

队列底部将当前阶段与最近操作结果分成两行，后台刷新不覆盖添加、重试或停止反馈；长文字可悬停查看完整内容。混选重试会区分无需重试的项目与实际占用，停止请求优先显示。任务列表按Enter打开结果（尚无结果时查看详情），密码列表按Enter使用所选密码；与双击一致，Ctrl+Enter仍执行当前页主操作。选择容器解压后，操作列与详情会明确显示该模式；修改操作仍需点击开始全部。“打开结果”会打开结果目录，文件结果则在文件管理器中精确选中实际生成的文件（包括重名后新名称）。任务操作菜单可分别定位来源首项和问题文件/目录，便于找到嵌套失败包；路径已移动或无法访问会明确显示完整路径，不跳到父目录。

- 通过内容识别 ZIP、7z、RAR、GZIP、BZIP2、XZ、TAR、Zstandard、LZ4、LZ5、Lizard 等格式；不信任文件扩展名。
- 支持改后缀、载体内追加的 ZIP/7z/RAR，以及已知 apate 头部伪装。ZIP/ZIP64 可从尾部定位，兼容大体积视频前缀和尾部杂数据；部分倒序或覆盖文件头的 7z 可重建输入视图。识别后直接从只读视图解压，不先复制整个大包。
- ZIP先读取元数据，普通包和仅识别/另存跳过密码预检。已知不超过1MiB的低成本加密条目先尝试前4个排序密码，通过头部后仍由成熟引擎校验完整条目；失败再并行筛选其余候选。大条目沿用批量预检，避免额外强制预读；最终解压仍校验全部正文。
- 密码本提供搜索、默认遮住的已有密码列表、使用次数及关联目录，可导入或拖入 UTF-8 文本（每行一个，包含 OnlyUnzip 导出文件，单文件最多16MiB）。新增草稿先显示预计新增/重复数量，预览不写库，保留密码首尾空格，实际保存结果另行显示。导入会验证实际文本，拒绝二进制伪装文件；多个文本逐项报告成功与失败，已导入的结果保留，混合拖入明确统计跳过的非TXT项。空输入/全重复不写盘，保存失败可保留草稿后重试。可选中一条密码点击“所选密码用于本批”或双击，返回队列后作为优先候选，输入框仍遮住密码。筛选/导入后保留同一密码的选择，运行中不可改动本批密码。成功密码自动记住；Windows DPAPI 保存到 `%LOCALAPPDATA%/T解压/passwords.dpapi`。
- 自动密码提示识别文件名关键词及同目录的 password.txt、密码.txt、解压密码.txt、说明.txt；只读取最多64KiB的有效UTF-8文本，处理BOM且保留裸密码首尾空格。坏文本或暂时锁定的提示会跳过，继续使用其他来源。文件名另补去除已知归档/分卷后缀的候选，同时保留原始候选；成功验证后才记入密码本。
- ZIP 有头部候选筛选，AES 预检使用 Windows CNG 并行处理，兼容现有 ZIP 的 UTF-8/系统编码密码；保存的仍是原密码。7z/RAR 使用排序、成功密码复用和低成本条目验证。最终都执行完整解压校验。
- 自动解压新产生的嵌套包；正常 DOCX/APK/EPUB 等容器默认保留。明确需要拆容器时，右键任务选择“明确按压缩容器解压”。
- 标准分卷自动归组；旧式 RAR 的 `.rar/.r00/.r01` 全部加入时，也会按引擎确认的根包卷组归为一次解压，保留合并前的选择。不同操作及不同手工顺序继续保留。`.part1.jpg / .part2.txt` 等 RAR 按内容配组。7z 支持编号 MP4、混合后缀和改名的末卷/中间卷，只有长度、元数据校验与候选归属唯一时才自动配对。缺卷显示缺失字节；有多种可能时打开“分卷顺序”，列表显示首卷、文件名、大小和目录，可多选整组移动/移除，也可拖入或粘贴补充。仅点击“按文件名排序”才执行自然排序，之后需核对首卷。返回后保留未保存草稿，保存后才更新队列，源文件保留原名。
- 所有嵌套解压成功、输出完成后，按选项将实际参与的原包移入回收站。后续队列任务仍需读取同一源时先保留，并显示原因；检查名单来自引擎实际读取的卷和嵌套源。失败/取消不启动清理；已完成任务的处理结果单独显示。
- “仅识别”读取元数据；添加文件夹使用同一套内容识别与分卷归组。扫描中单个文件变化或属性不可读会跳过并显示首个问题路径，继续检查其他文件；根目录或遍历错误、取消不会被当作完整成功。“另存原包”输出恢复格式后的新文件（RAR、ZIP 原生多卷另存为完整卷组）；“新建压缩包”支持 ZIP/7z。
- Ctrl+O 在当前页添加文件、分卷、导入密码或选择任务目录；Ctrl+Enter 开始队列、保存分卷顺序、保存新增密码或保存任务设置并待开始；Ctrl+F 查找队列/密码；Ctrl+A 全选当前队列视图或分卷，Ctrl+↑/↓ 移动选中任务/分卷，Delete 只移除列表项。两个列表支持 Ctrl+V 粘贴资源管理器复制的文件或逐行“复制为路径”，编辑框仍正常粘贴文本。Tab 导航；小屏或高 DPI 下内容可以用原生滚动条查看，焦点会滚入视野。

当前边界：缺失的正文、首卷或未知密码需要补充；完全改名且缺少足够关联信息的切片需手工排序。头部恢复后仍必须通过正文校验。自动嵌套深度上限 32。Brotli 原始流缺少稳定 magic，未自动猜测。创建加密 ZIP 的密码限 ASCII（可含空格与特殊符号），中文密码请创建 7z。未做签名安装包、右键菜单注册或对外发布。

构建使用 MinGW-w64、CMake、Ninja，依赖 bit7z v4.0.10 和 7-Zip ZS26.05。本机依赖已准备好；Python 仅用于开发测试，集成测试需要 `cryptography`，重新生成图标另需 Pillow：

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 8
ctest --test-dir build --output-on-failure
python -X utf8 tests/benchmark.py
python -X utf8 scripts/package.py
```

`tests/download_fixtures.py` 从固定版本的 bit7z 官方测试数据下载 RAR 样本。所有测试只创建/保留测试数据，默认不回收输入。真实回收验证需要另行针对样本确认。

0.13.0 已通过292项功能检查：92解压回归、76交互模型、17原生COM/HDROP、55正式队列流程、22布局/DPI、18工作台存储恢复、12打开协议/门禁/原生定位准备，另加图标资源校验。本轮覆盖内层单独重试、设置继承与就地输出、会话恢复、重名保留、取消新目录、来源变化及深层成功后错误路径恢复，既有密码/伪装/分卷流程保持。布局复用正式几何与GDI字体，覆盖100%–300%。当前小AES ZIP密码测量见 `docs/evidence/zip-priority-performance.json`，仅说明该样本。测试保留源、关闭回收，不打开真实剪贴板或启动GUI，不使用CU；实际拖放手感、跨屏DPI、菜单/消息投递及Explorer选中效果仍未操作。

0.3.0 的真实样本记录：`<CORPUS_ROOT>` 顶层 16 个归档相关文件全部识别为 13 组；10 组已完整解压，含嵌套共 19 个包、4095 个输出文件、25,603,967,721 字节，19 包完整 CRC/MAC 校验通过。其余三组分别为现有密码未通过、缺首卷、倒序包正文校验失败。0.4.0 沿用格式与密码验证规则，没有重复写出这批大文件；实际 RAR 多卷的新增回收判断接口另以保留原包的集成检查覆盖。真实原包仍保留，详情见 `docs/ai/progress.md`。

命令行可以单独做全量校验，仅读取压缩包，不生成解压文件：

```powershell
.\build\bin\unpack_cli.exe inspect "D:\路径\伪装文件.mp4" --verify --keep
```

需求、来源研究和可继续开发的状态在 `docs/ai/`，REA 实际检查、测试和基准报告在 `docs/evidence/`。REA 已执行本地 PE/资源/导入和 apate 托管元数据检查；没有将这些检查称为完整 Python 源码恢复。本地 EXE 与公开 1.x 源码无法逐字证明相同。

bit7z 使用 MPL2；本项目仅扩展其本地卷路径解析/观测接口，用于改名 RAR 多卷及准确记录参与卷。修改保留原许可，补丁位于 `patches/bit7z-volumes.patch`。解压引擎许可见随程序的 `7-Zip-License.txt`。参考实现及源码链接见 `docs/ai/requirements-and-route.md`。
